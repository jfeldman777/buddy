# Техзадание 001 — Buddy

**BUDDY — техническое задание для Cursor**
Alpha 0.01 — редакция от 15 октября 2026 года

- Репозиторий: https://github.com/jfeldman777/buddy
- Планируемый сайт: https://jfeldman777.github.io/buddy/
- Название: Buddy
- Имя ИИ-партнёра: Би
- Слоган: «Опыт трудных побед»

Статус: проект требований для согласования. Cursor должен сначала представить план, а не немедленно писать код.

> Поправки и решения, принятые при согласовании плана, собраны в [architecture.md](architecture.md).

## 1. Назначение проекта

Buddy — персональный ИИ-партнёр, который помогает человеку приобретать опыт самостоятельного преодоления трудностей.

Главный принцип: не делать за человека то, что он способен и хочет сделать сам.

Би должен:

- Знакомиться с человеком в естественном диалоге.
- Проявлять собственную инициативу.
- Предлагать задачи, игры и совместные занятия.
- Помогать преодолевать трудности, не лишая человека удовольствия от самостоятельной победы.
- Учиться лучше понимать пользователя.
- Объяснять свои поступки.
- Принимать замечания и пересматривать решения.

Alpha 0.01 — минимальная работающая версия для испытаний с небольшой группой пользователей.

Полную систему ТУАИ, социальные связи между пользователями и расширенную диагностику пока не реализовывать.

## 2. Репозиторий и безопасность

Репозиторий Buddy остаётся Public.

Публичными являются:

- Исходный код интерфейса.
- Стартовая страница.
- Декларации поведения Би.
- Описание проекта.
- Автоматические тесты.

Закрытыми остаются:

- API-ключи и другие секреты.
- Личные данные пользователей.
- Содержание разговоров.
- Журналы событий и решений.
- Финансовые записи.
- Административные операции.

GitHub Pages используется для размещения статического интерфейса PWA.

Для работы с ИИ, финансированием и авторизацией необходим отдельный серверный компонент, например Cloudflare Workers.

Секреты хранятся только в защищённой конфигурации сервера. Они никогда не передаются браузеру.

## 3. Стартовая страница

Разместить:

> **Buddy**
> Опыт трудных побед

Короткое пояснение:

> «Би — ваш ИИ-партнёр. Он помогает справляться с трудностями, находить решения и приобретать собственный опыт трудных побед».

Элементы:

- «Познакомиться с Би».
- «Установить Buddy».
- QR-код для открытия сайта на смартфоне.
- Краткое объяснение условий работы и оплаты.

Приложение должно открываться и без установки.

Подготовить PWA-манифест, service worker и значки 192×192 и 512×512.

Значок: ярко-зелёный квадрат, белый круг с чёрной границей, внутри строчные чёрные буквы db.

На Android и iPhone должны отображаться корректные инструкции установки. Не обещать автоматическую установку там, где браузер её не поддерживает.

## 4. Первое знакомство

Знакомство начинается не с анкеты, а с инициативы Би.

Пример:

> Би: «Привет! Я Би. Сначала выбери, каким голосом мне говорить».

Пользователь прослушивает доступные варианты голоса и выбирает один.

После этого Би впервые говорит выбранным голосом:

> Би: «Вот теперь можем познакомиться. А как мне тебя называть?»

Далее — естественный диалог.

Требования:

- Предложить несколько доступных голосов.
- Сохранять выбор.
- Позволять менять голос позднее.
- Сохранять имя пользователя.
- При следующем запуске узнавать пользователя.
- Поддерживать текстовый режим, если голос недоступен.
- Запрашивать разрешение на микрофон только при необходимости.

Для Alpha 0.01 допустимо использовать браузерные средства синтеза и распознавания речи с учётом различий между устройствами.

Использование камеры пока не обязательно. В будущем Би сможет предложить игру с угадыванием возраста, но только с явного разрешения пользователя.

## 5. Два способа финансирования

Перед началом платного общения пользователь выбирает способ финансирования.

### Вариант А. Пользователь платит сам

Пользователь выбирает сумму: $5, $10 или $15.

В Alpha 0.01 оплата подтверждается вручную.

Порядок:

1. Пользователь выбирает сумму.
2. Buddy создаёт заявку с уникальным номером.
3. Пользователь получает инструкцию по переводу денег разработчику.
4. Пользователь сообщает, что перевод выполнен.
5. Разработчик проверяет поступление денег.
6. Разработчик подтверждает платёж в административном интерфейсе.
7. Buddy открывает доступ с соответствующим лимитом.

До подтверждения заявка имеет статус ожидания.

Не создавать фиктивных подтверждений оплаты.

Платёжные реквизиты разработчик укажет отдельно. Не записывать их в код заранее.

### Вариант Б. Пользователь просит разработчика оплатить участие

Порядок:

1. Пользователь выбирает «Прошу разработчика оплатить».
2. Buddy создаёт заявку.
3. Разработчик получает уведомление.
4. Разработчик решает, одобрить заявку или отклонить.
5. При одобрении разработчик сам выбирает лимит: $5, $10 или $15.
6. Buddy уведомляет пользователя об одобрении и установленном лимите.
7. Пользователь получает доступ к общению с ИИ.

В этом варианте пользователь не выбирает размер бюджета.

### Общие правила финансирования

- Функциональность Би одинакова при обоих способах оплаты.
- Лимит относится к расходам на платные ИИ-операции.
- Расходы учитываются сервером отдельно для каждого пользователя.
- Пользователь видит лимит, расход и остаток.
- При исчерпании лимита новые платные запросы блокируются.
- Автоматическое увеличение лимита запрещено.
- Повторное подтверждение одной заявки не должно повторно начислять бюджет.
- Предусмотреть защиту от параллельных запросов, способных превысить лимит.
- Если невозможно достоверно рассчитать стоимость операции, новые платные операции блокируются до выяснения.

**Важно:** $5/$10/$15 в этой версии — установленный бюджет использования ИИ. Учёт перечисленных пользователем денег и учёт стоимости запросов должны быть раздельными.

Условия возврата неиспользованных средств должны быть явно показаны пользователю до перевода денег.

## 6. Административный интерфейс

Создать защищённую страницу разработчика.

Функции:

- Просмотр новых заявок.
- Просмотр выбранной пользователем суммы при самостоятельной оплате.
- Подтверждение фактически полученного платежа.
- Одобрение или отклонение просьбы о финансировании.
- Выбор лимита при оплате разработчиком.
- Просмотр расходов и остатков.
- Приостановка доступа.
- Просмотр технических ошибок.
- Просмотр только тех записей журнала, которые пользователь разрешил передать.

Доступ к административным операциям — только после серверной проверки полномочий.

Скрытая ссылка или пароль, проверяемый исключительно в браузере, недостаточны.

## 7. Декларации поведения Би

Создать отдельный файл деклараций с постоянными идентификаторами.

- **D1. Разрешения.** Би не использует микрофон или камеру без разрешения.
- **D2. Конфиденциальность.** Би не передаёт разработчику личные данные и журналы без согласия пользователя.
- **D3. Память.** Би сохраняет разрешённые предпочтения и использует их при следующих встречах.
- **D4. Достоверность.** Би различает факты, предположения и неизвестное.
- **D5. Исправляемость.** Би принимает замечания и способен пересмотреть решение.
- **D6. Самостоятельность человека.** Би помогает человеку преодолевать трудности, но не отнимает у него возможность самостоятельного действия.
- **D7. Инициатива.** Би предлагает новые действия и занятия, уважая отказ пользователя.

Декларации должны быть доступны пользователю и использоваться при проверке поступков Би.

## 8. Журнал событий, решений и мотивов

Журнал ведётся автоматически и хранится локально.

Для каждого существенного поступка Би фиксируются:

- Время и идентификатор события.
- Ситуация и наблюдаемые факты.
- Цель Би.
- Принятое решение.
- Заявленный мотив решения.
- Связанные декларации D1–D7.
- Фактически выполненное действие.
- Результат действия.
- Оценка пользователя, если получена.

Не требовать от модели раскрытия скрытых внутренних рассуждений. Вместо этого Би должен давать краткое, проверяемое объяснение принятого решения.

Фактические события — например, получение разрешения, отправка данных или обращение к ИИ — регистрируются программой независимо от объяснений модели.

Предусмотреть просмотр и экспорт журнала.

## 9. Оценка пользователя

После значимых эпизодов Би может спросить:

> «Это было кстати?»

Варианты:

- Да.
- Нет.
- Не знаю.

Дополнительно пользователь может оставить комментарий.

- Не запрашивать оценку после каждой реплики.
- Каждая оценка связывается с конкретным событием.
- Отрицательная оценка не означает автоматически нарушение деклараций: спарринг-партнёр может предлагать трудные или спорные действия.

## 10. Права доступа к журналу

Утверждённое правило:

Полный журнал принадлежит пользователю и остаётся на его устройстве.

Разработчик может получить:

- Обезличенную техническую статистику.
- Отдельные записи, добровольно отправленные пользователем.
- Другие данные только при отдельном информированном согласии.

Отказ от передачи журнала не должен лишать пользователя обычных функций Buddy.

В будущем предусмотреть отдельный режим для родителей. В Alpha 0.01 родительский кабинет не реализовывать.

## 11. Локальная память

Использовать IndexedDB для хранения:

- Имени.
- Выбранного голоса.
- Настроек.
- Истории диалога.
- Журнала событий и решений.
- Оценок пользователя.
- Разрешений и согласий.

Предусмотреть удаление данных и экспорт журнала.

Учитывать, что удаление приложения, очистка браузера или смена телефона могут уничтожить локальную память.

Синхронизация с компьютером переносится на следующую версию.

## 12. Серверная часть

Сервер отвечает за:

- Безопасное обращение к ИИ.
- Авторизацию пользователей и разработчика.
- Создание и обработку заявок.
- Уведомления разработчику.
- Учёт расходов.
- Контроль лимитов.
- Подтверждение доступа.
- Защиту от злоупотреблений.

У каждого пользователя должен быть устойчивый идентификатор и безопасный способ восстановить доступ после повторного открытия приложения.

Не считать случайный идентификатор в браузере полноценной защитой учётной записи.

При первом знакомстве можно предложить пользователю разрешить отправку разработчику уведомления о новом участнике. Передавать только явно согласованные сведения.

## 13. Тестирование

Обязательные проверки:

- Сайт открывается по QR-коду.
- PWA устанавливается на поддерживаемых устройствах.
- Пользователь выбирает голос и может начать разговор.
- Имя и голос сохраняются после перезапуска.
- При недоступном микрофоне работает текстовый режим.
- Заявка на самостоятельную оплату создаётся с правильной суммой.
- Доступ не открывается до подтверждения платежа.
- При оплате разработчиком лимит выбирает разработчик.
- Пользователь не может сам одобрить заявку.
- Расходы учитываются на сервере.
- Превышение лимита предотвращается.
- Существенные решения Би фиксируются в журнале.
- Оценка пользователя связывается с соответствующим решением.
- Журнал не отправляется разработчику без согласия.
- Секретные ключи не попадают в публичный код.
- Один пользователь не может получить доступ к чужим финансовым данным.

## 14. Что пока не делать

- Синхронизацию с домашним компьютером.
- Полную диагностику ТУАИ.
- Социальные знакомства через Buddy.
- Общение между двумя экземплярами Би.
- Родительский кабинет.
- Автоматическое распознавание возраста.
- Автоматические платежи банковской картой.
- Автономную работу Би вне приложения.

## 15. Порядок работы Cursor

Сначала только анализ и план.

Cursor должен:

- Проверить текущее состояние репозитория.
- Предложить минимальную архитектуру.
- Указать, какие внешние сервисы потребуются.
- Описать схему безопасной авторизации.
- Описать точный механизм контроля расходов.
- Указать, какие решения ещё требуются от разработчика.
- Разбить реализацию на небольшие этапы с проверяемыми результатами.
- Оценить минимальные расходы на инфраструктуру.

Не начинать реализацию до утверждения плана.

После утверждения выполнять этапы последовательно и проверять результат каждого этапа.

## Критерий готовности Alpha 0.01

Новый пользователь открывает Buddy на смартфоне, знакомится с Би, выбирает голос, оформляет один из двух вариантов финансирования, получает подтверждение, начинает общаться и может посмотреть журнал поступков Би со своими оценками.

Разработчик видит заявки и расходы, но не получает личный журнал без согласия пользователя.
