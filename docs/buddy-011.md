# Buddy-011 — А обучает Би: личная память и общие знания

Согласованный план реализации. Главный принцип: Би накапливает опыт во внешней памяти (D1), а не начинает заново после обновления сайта, Worker или смены модели ИИ.

Полный текст требований и этапы — в согласованном плане Cursor. Этот документ фиксирует решения для репозитория.

## Этап A (сделано)

- Миграция [`server/migrations/0005_buddy011_memory.sql`](../server/migrations/0005_buddy011_memory.sql): личная память, контекст незавершённых тем, teachings, KB, стратегии, кошелёк `buddy_chat_budget`.
- Бюджет А–Би **отдельно от DCB $10**. Стартовый грант для испытаний: **$1** (`CHAT_BUDGET_MICROS=1000000` в [`server/wrangler.toml`](../server/wrangler.toml)). Превышение запрещено (`reserveChatStrict`).
- Согласие на серверную память: `GET/POST /chat/consent`, текст версии `buddy-011-memory-v1`.
- Просмотр кошелька: `GET /chat/budget` (нужна сессия пользователя).

## Этап B (сделано)

- Промпт и OpenAI для А: [`server/src/bi/prompts.js`](../server/src/bi/prompts.js), [`openai.js`](../server/src/bi/openai.js) (кошелёк chat).
- API: `GET /chat/context`, `POST /chat/turn` (текст, фото, `open: true` для инициативы Би).
- UI на главной: согласие → «Продолжить разговор» → поле ввода, фото из файла и с камеры (D1).
- Контекст незавершённых тем пишется в `bi_conversation_context`; гипотезы памяти — в entries.

## Этапы C–D (не начинать без разрешения)

- **C** — карты памяти, обучение; тесты наличия в промпте **и** практические испытания правильности применения.
- **D** — propose / admin approve-revoke с per-turn распространением.

## Разделение данных

| Область | Хранилище | Бюджет OpenAI |
|---------|-----------|---------------|
| Личная память А, context, teachings | D1 `bi_*` | `buddy_chat_budget` |
| Общие знания / стратегии | D1 `kb_*`, `bi_strategies` | — |
| DCB протоколы Си | D1 `dcb_*` | `dcb_budget` ($10) |
| Журнал деклараций, имя на устройстве | IndexedDB | — |

## Согласие

Без `bi_memory_consent` актуальной версии сервер не должен сохранять личную память (проверка на этапах B+). Этап A предоставляет API согласия и схему.
